# CloudOps Production Simulation Lab

A production-style cloud operations project built to demonstrate junior cloud engineering, cloud support, infrastructure, and troubleshooting skills using AWS.

## Project Summary

This project deploys a student records web application on AWS using EC2, Nginx, Node.js, Amazon RDS MySQL, private Amazon S3 storage, IAM roles, and CloudWatch monitoring.

The goal is not to build a complex application. The goal is to prove cloud infrastructure, deployment, monitoring, security, and troubleshooting skills in a realistic environment.

## Live Architecture

```text
User Browser
   ↓
EC2 Public IP - Port 80

Node.js Express App - PM2 Process Manager
   ↓

   ↓

   ↓

```

## Infrastructure Design

### VPC and Networking

A custom VPC was created with:

* Public subnet for EC2
* Private subnets for RDS
* Internet Gateway for public web access
* Public route table for EC2 internet traffic
* Private route table for RDS subnets
* Security group isolation between EC2 and RDS

RDS is not publicly accessible. The database only accepts MySQL traffic from the EC2 application security group.

### EC2 Application Server

The application runs on an Ubuntu EC2 instance. It uses:

* Node.js for backend runtime
* PM2 to keep the app running in the background
* Nginx as a reverse proxy
* Port 80 for public browser access
* Port 3000 only for internal Node.js runtime

Public users access the app through Nginx, not directly through the Node.js port.

### RDS Database

The original local MySQL database was migrated from the EC2 instance to Amazon RDS MySQL.

The app connects to RDS using environment variables. RDS is deployed inside private subnets and protected by a dedicated database security group.

### S3 Image Storage

Student images are uploaded to a private S3 bucket.

The bucket blocks public access. Images are displayed in the app using temporary signed URLs generated by the backend.

This avoids exposing the bucket publicly while still allowing users to view uploaded images.

### CloudWatch Monitoring

CloudWatch Agent was installed on EC2 to collect:

* PM2 application logs
* PM2 error logs
* Nginx access logs
* Nginx error logs
* Memory usage metrics
* Disk usage metrics

Custom metrics are stored under the namespace:

```text
CloudOps/StudentRecords
```

## Security Measures

* RDS is private and not publicly accessible.
* S3 bucket has Block Public Access enabled.
* EC2 uses an IAM role instead of hardcoded AWS credentials.
* Application secrets are stored in `.env` and excluded from Git.
* `.env.example` is included with placeholder values only.
* SSH is restricted to the user's IP.
* Port 3000 is not intended for public access after Nginx is configured.
* RDS only allows MySQL traffic from the EC2 security group.

## Environment Variables

Create an `.env` file inside the `app/` folder.

Use this template:

```env
DB_HOST=replace_with_database_host
DB_USER=replace_with_database_user
DB_PASSWORD=replace_with_database_password
DB_NAME=cloudops_students
PORT=3000
APP_ENV=replace_with_environment
AWS_REGION=us-east-1
S3_BUCKET_NAME=replace_with_s3_bucket_name
```

Do not commit `.env`.

## Cost Control Notes

This project uses AWS resources that may incur charges.

To reduce cost:

* Stop EC2 when not working
* Stop RDS when not working
* Avoid NAT Gateway
* Avoid Elastic IP unless needed
* Delete unused snapshots
* Monitor AWS Budgets
* Remove test objects from S3 when finished
